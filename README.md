# «Вершина»: регистрация на олимпиаду

Готовый статический сайт для GitHub Pages. Посетители видят общую таблицу без входа в ChatGPT и GitHub. Менять данные может владелец GitHub-аккаунта `daniilshegolev2018` с ключом, имеющим доступ к записи в репозиторий.

## Что уже сделано

- Стиль по официальному сайту «Вершины»: тёмно-синий, голубой, красный; официальный логотип хранится вместе с сайтом.
- Отдельные таблицы по двум корпусам, поиск по классу и ФИО руководителя.
- Редактор класса, руководителя, численности и числа регистраций.
- Автоматические проценты по классам, корпусам и всей школе.
- Зелёный: от 70%; жёлтый: от 55% до 70% (не включая 70%); красный: ниже 55%.
- Незаполненные значения отличаются от нуля. При неполных данных общий процент не выдаётся за окончательный.
- Черновик правок и явная кнопка «Сохранить для всех». Сохранение создаёт новую версию файла `data.json` в GitHub.
- Защита от перезаписи более новой версии таблицы, проверка численности и повторяющихся классов.
- CSV для Excel, резервная копия JSON, печать через браузер.
- Адаптация к телефону и клавиатурное управление.

## 1. Размещение

1. Создайте новый **публичный** репозиторий `vershina-monitor` в аккаунте `daniilshegolev2018`, с основной веткой `main`. Не используйте репозитории других проектов.
2. Загрузите файлы из архива непосредственно в корень репозитория. Файл `index.html` должен быть в корне, а не внутри дополнительной папки.
3. В репозитории откройте **Settings → Pages**.
4. В разделе **Build and deployment** выберите **Deploy from a branch**, ветку **main**, папку **/(root)**, затем **Save**.
5. Дождитесь завершения публикации и откройте адрес, который покажет GitHub Pages. Он не требует входа в ChatGPT.

Сборка и установка библиотек для размещения не нужны. Сервер и отдельная база данных не нужны. Если выбрано другое имя репозитория, аккаунт или ветка, измените `config.json` до размещения.

## 2. Доступ редактора

Ключ создаёт владелец в собственном GitHub. **Не присылайте ключ в чат и не добавляйте его в файлы проекта.**

1. GitHub → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. Resource owner: **daniilshegolev2018**.
3. В **Repository access**: **Only select repositories**, затем только **vershina-monitor**.
4. В **Repository permissions**: **Contents → Read and write**. Другие разрешения не нужны; Metadata автоматически доступно для чтения.
5. Выберите ограниченный срок действия и создайте ключ. Скопируйте его в своём браузере.
6. На сайте таблицы нажмите **Вход для редактора** и введите ключ. Приложение проверяет аккаунт и наличие доступа к записи.

Ключ отправляется только на `https://api.github.com` и хранится только в памяти текущей вкладки. Он очищается при выходе или перезагрузке; приложение не записывает его в localStorage, sessionStorage, файлы, URL или репозиторий. Поле ввода также очищается после входа и закрытия окна. Для нового сеанса редактора ключ вводится заново.

Режим просмотра не имеет кнопок изменения. Возможность сохранения определяется правами GitHub, а не только скрытием кнопок. Посторонний ключ другого аккаунта редактор не принимает. Нельзя использовать ключ от другого человека.

## 3. Работа с таблицей

1. Войдите как редактор.
2. Нажмите **Добавить класс**, выберите корпус и заполните поля. Отсутствующие данные оставляйте пустыми. Если регистраций нет, введите **0**.
3. Нажмите **Применить**, чтобы обновить черновик.
4. После всех правок нажмите **Сохранить для всех**. Только после подтверждения GitHub сайт сообщает об успешном сохранении.
5. Посетители при открытии или обновлении таблицы получают текущий `data.json` через GitHub API. При недоступности API показывается последняя версия, опубликованная GitHub Pages, с предупреждением. В этом случае обновление статического файла после коммита может занять несколько минут.
6. **Отменить изменения** возвращает последний загруженный/сохранённый вариант. Удаление класса до публикации также можно отменить этой кнопкой.
7. **Резервная копия JSON** скачивает текущую таблицу вместе с черновыми правками. Она полезна перед обновлением данных после конфликта.

Если GitHub сообщает о конфликте версий, черновик остаётся открытым и автоматически не перезаписывает более новые данные. Скачайте резервную копию, обновите таблицу и внесите нужные правки повторно.

## Исходные данные

В `data.json` пока нет реальных классов: страница школы со списком классов и руководителей была недоступна при подготовке первой версии. ФИО, корпус, численность и регистрации не выдуманы. Их нужно добавить после получения списка. Школьная сводка означает сумму **всех классов, добавленных в таблицу**; для полного охвата школы необходимо добавить весь необходимый список классов.

Данные и история их изменений в публичном репозитории доступны посетителям. В таблице предусмотрены только класс, ФИО классного руководителя и агрегированные числа — имена учеников и персональные списки участников добавлять не требуется.

## Файлы

- `index.html`, `style.css`, `app.js` — интерфейс.
- `core.js` — расчёты и проверка данных.
- `github.js` — чтение и сохранение в GitHub.
- `config.json` — аккаунт, репозиторий и ветка.
- `data.json` — общая таблица.
- `vershina-logo.svg` — официальный логотип из открытого ресурса сайта олимпиады: https://static.tildacdn.com/tild3831-3063-4032-b539-366332623062/Frame_1597883503.svg
- `favicon.svg` — небольшая иконка страницы.
- `.nojekyll` — отключение обработки Jekyll.
- `tests/` — проверки расчётов, валидации, разграничения доступа, сохранения и конфликтов.

## Проверки разработчика

Для проверки без установки зависимостей (Node.js 22+):

```sh
npm run check
npm test
```

Публикация на Pages использует файлы напрямую. `package.json` и папку `tests/` можно оставить в репозитории; они не нужны посетителям страницы.

Документация: https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages

Источник оформления: https://mo-mathvector.ru/olymp

Сайт таблицы — рабочий инструмент лицея, а не официальный сайт организатора олимпиады.
